# Improved Prompt

## Objective

Continue the Croatian-first i18n rollout in `tejospec/apps/web` by eliminating remaining hard-coded German UI/content on key customer-facing support pages (Contact + FAQ), while ensuring no raw i18n keys leak at runtime.

## Scope

- Convert `apps/web/src/pages/contact.tsx` and `apps/web/src/pages/faq.tsx` from hard-coded German strings to i18n keys using `useTranslation('common')`.
- Ensure both pages properly preload translations using `getCommonTranslations(locale)` via `getStaticProps`.
- Add all required keys and translations to:

  - `apps/web/public/locales/hr/common.json` (Croatian source of truth)
  - `apps/web/public/locales/en/common.json` (fallback baseline)

## Constraints

- Keep Croatian (`hr`) as the primary language.
- Avoid key leaks: ensure all newly introduced keys exist in **hr**; for non-hr locales, rely on `fallbackLng` (de/es/fr/it/sl/hu/ro -> en -> hr) so no keys render.
- Prefer using `getCommonTranslations(locale)` instead of direct `serverSideTranslations` calls.
- Keep changes localized to these pages + translation JSON; do not refactor unrelated modules.

## Acceptance Criteria

- Contact and FAQ pages contain no hard-coded German UI strings in JSX/meta/labels (all moved behind `t(...)` keys).
- Both pages include `getStaticProps` returning `{ ...(await getCommonTranslations(locale)) }`.
- `pnpm nx run @tejo/web:typecheck` passes.
- `pnpm nx run @tejo/web:lint` passes.

## Implementation Notes

- Use new top-level translation trees to avoid collisions with existing keys:

  - `contactPage.*`
  - `faqPage.*`

- Keep stable IDs for FAQ categories/questions to preserve UI behavior (open/close state, filtering).
